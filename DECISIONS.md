# Decisions

**Loom walkthrough:** https://www.loom.com/share/6b0bb2ad320c4fa68fc2845a2a3e2877
**Model comparison (one page):** https://claude.ai/artifact/MZnq3agMMBHrVEUGR295ZC

**What I built, and why.** I built a structured, verifiable risk review inside the existing chat. Instead of a wall of numbered prose, a risk review now returns an interactive table: risks sorted worst first, filterable by severity, each with a short reason and the clause it relates to. Clicking a clause opens that page of the PDF with the passage highlighted, and reviews are saved and listed in the sidebar, so they survive a refresh. I chose this because a risk review is one of the most common things a property lawyer asks of a document, and a finding is only useful if the lawyer can check it. I considered inline citations, a multi-document review and a deal view instead. I chose a single-document review because it is a core lawyer task I could finish properly in the time, and a deal entity can sit on top of it later.

**Key decisions and the alternatives I rejected.** The model passes every risk to a `present_risks` tool as typed data, rather than writing JSON or a markdown table into its reply, which would be fragile, unvalidated and have no stable IDs to link findings to the document. The tool saves the findings and works out each page by locating the quote in the PDF text, because an early eval showed the model was unreliable at attributing pages, especially near page boundaries. The saved table streams to the browser as its own event rather than through the model, and messages store typed parts that reference the review, so new kinds of rich output are easy to add. I tried fuzzy matching with `rapidfuzz` but rejected it after testing. I also switched to Haiku 5.5. The evals showed it copied every quote exactly, found about 46% more risks and cost about 4× less per review than the starter's Haiku 4.5, at the price of being about 38% slower. The document is now prompt-cached. I assumed a single user with no authentication, and text-based PDFs.

**What I'd do next.** First, review the output with a legal engineer: the evals prove the quotes are real, not that the risks and severities are right, and their judgements would become the eval's answer key. Next, make citations exact by design: number the paragraphs at upload so the model cites an ID instead of copying text (written up in `docs/ARCHITECTURE.md`). Then let lawyers accept, dismiss and export findings; group documents into a deal so a whole transaction can be reviewed at once; handle long documents section by section; and send chat history as real message turns so the whole conversation is cached.
